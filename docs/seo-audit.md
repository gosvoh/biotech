# Технический SEO-аудит — 16 сентября 2026

## Подтверждённые проблемы production

Проверено до изменений, исходный commit: `65b34db9aa86f66b46b07ad6e62a0d8957213f10`.

- Главная возвращала HTTP 200, но не содержала canonical и `og:url`.
- `og:image`, `twitter:image`, все семь адресов sitemap и ссылка Sitemap в robots указывали на удаляемый хост.
- Sitemap не содержал новости и сотрудников. Всем статическим страницам присваивалась дата генерации вместо даты изменения.
- В новости `cmr1wrc0w0009me01oxmfizud` OG/Twitter image ссылался на HTML-страницу. Её реальный маршрут `/opengraph-image` отвечал HTTP 500.
- Для сокращённого тестового User-Agent `TelegramBot` метаданные новости находились после `</head>`. Полный User-Agent `TelegramBot (like TwitterBot)` распознаётся стандартным обработчиком Next.js по TwitterBot; проверка выполняется именно с ним. Streaming не считается доказанной причиной проблемы Telegram.
- Генераторы изображений новостей и сотрудников синхронно читали `params.id`, хотя Next.js 16 передаёт Promise.
- Заголовки повторяли название сайта из-за одновременного применения полного title и root template.
- Главные `/opengraph-image` и `/twitter-image` на действующем production-хосте уже возвращали HTTP 200 и PNG 1920×960. Ошибка ссылки в metadata не означала отсутствия этих ресурсов.

Это подтверждённые технические препятствия корректному обнаружению URL и построению превью. Причину отсутствия конкретной страницы в индексе нельзя окончательно установить без отчётов Search Console/Яндекс Вебмастера и журналов обхода. Отсутствие canonical само по себе не запрещает индексацию. Доступность сайта для отдельного HTTP-клиента не доказывает доступность со всех адресов поисковых роботов или Telegram.

## Изменения

- `src/lib/site.ts`: единственный `SITE_URL`; сборка абсолютных URL только из относительных путей. Внешние адреса, query и fragment в SEO-пути отвергаются. Значение не зависит от Host или переменных окружения.
- Root layout и `generateMeta` используют `new URL(SITE_URL)`.
- Canonical и `og:url` соответствуют странице. На корне Next.js сериализует origin без завершающего `/`; это эквивалентный корневой URL, проверка нормализует его через URL API.
- OG image: путь страницы + `/opengraph-image`; Twitter image: путь страницы + `/twitter-image`. На главной используются корневые маршруты. Размер, title, description, type и alt указаны явно.
- Существующие title сохранены без повторного наложения шаблона. Неподтверждённые Twitter-аккаунты исключены из метаданных; локальный favicon теперь имеет абсолютный путь от корня.
- Динамические страницы используют общий генератор; отсутствующие сотрудники, отсутствующие и скрытые новости возвращают notFound, включая маршруты изображений.
- Изображения корректно ожидают params. Генератор и существующие локальные шрифты/логотип сохранены.
- Стандартная обработка ботов Next.js сохранена. Ручное расширение htmlLimitedBots не требуется для полного User-Agent Telegram и конфликтует с распознаванием ботов при Partial Prerendering в этой версии.
- Sitemap получает видимые новости и сотрудников из существующей БД, использует их `updatedAt`. Статические страницы не получают выдуманный lastModified. Кэш обновляется по существующим тегам `news`/`members` и временному профилю `minutes`. Ошибки БД не скрываются под успешным неполным sitemap.
- Robots разрешает публичные страницы, исключает `/admin` и `/api/`, указывает актуальный sitemap. Админка дополнительно имеет noindex/nofollow; это не заменяет авторизацию.
- JSON-LD в проекте не было; новая разметка не добавлялась.
- Удаляемый хост встречался только в root layout, helper metadata, robots, sitemap, двух динамических страницах и SEO-тестах. После изменений поиск по исходникам и конфигурации не находит его. Внешний сервис чата на другом домене не изменён.
- В коде Auth.js, fetch, статических ресурсах и почтовой конфигурации зависимостей от удаляемого хоста не найдено. Значения production env и произвольные URL в production БД недоступны этому аудиту; их отсутствие там не утверждается.

## Проверки

Используются Bun и существующие scripts. Для локальной проверки создана отдельная SQLite БД, применены существующие миграции; добавлены только локальные тестовые новость, скрытая новость и сотрудник. Production БД не менялась.

- `bun install --frozen-lockfile`.
- `bun run db:generate`, `bun run db:deploy` с локальным DATABASE_URL.
- `bun run test`: 31 тест, включая метаданные, динамические сущности, исключение скрытых/отсутствующих записей, sitemap, robots и запрет возвращения удаляемого домена.
- `bun run lint`: 0 ошибок; 3 существующих предупреждения о неиспользуемых импортах главной страницы.
- `bun run build`: успешная production-сборка и проверка TypeScript. Существуют предупреждения о типе модуля tailwind.config.ts и tracing маршрута uploads; вне области SEO-изменений.
- Standalone-сервер также проверен под Bun. Для отсутствующих и скрытых страниц Next.js с Partial Prerendering может вернуть streaming HTTP 200 с `noindex`; их image-маршруты возвращают 404. Скрытая запись отсутствует в sitemap.
- `bun run seo:check <base-url> /news/<existing-id> /team/<existing-id>` проверяет настоящий HTML без JavaScript от имени `TelegramBot (like TwitterBot)`, canonical/OG в head, robots/sitemap и бинарные PNG с ожидаемыми размерами. Проверены семь статических и две динамические страницы, 18 изображений.

## После deployment

1. Проверить главную, все семь публичных разделов, существующую новость и сотрудника. Выполнить `bun run seo:check <production-origin> /news/<id> /team/<id>`.
2. Проверить `/robots.txt`, `/sitemap.xml`, `/opengraph-image`, `/twitter-image`, а также оба image-маршрута новости и сотрудника. Изображения должны отвечать 200/image/png без cookies, авторизации и перенаправлений.
3. В Google Search Console для действующего домена отправить `/sitemap.xml`, проверить главную и примеры динамических URL через URL Inspection, запросить индексацию. Проверить выбранный Google canonical и причины исключения страниц. [Инструкция Google](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).
4. В Яндекс Вебмастере отправить актуальный Sitemap, проверить robots и индексирование, отправить важные страницы в «Переобход страниц».
5. В Telegram отправить ссылку новым сообщением с включённым превью. Если остался старый результат — попробовать обновление через [WebpageBot](https://t.me/WebpageBot), затем отправить ссылку снова. Если превью по-прежнему нет, проверить серверные логи запросов TelegramBot, ограничения WAF и доступность картинки извне. Исправление сайта не гарантирует мгновенного сброса внешнего кэша.

DNS и nginx удаляемого хоста, production deploy и панели поисковых систем в эти изменения не входят.
